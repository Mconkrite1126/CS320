# CS 320: Software Testing, Automation, and Quality Assurance

This repository includes my contact service files and tests from Project One and my summary and reflections report from Project Two. These projects helped me understand how testing fits into building software. I am still learning, but I feel more comfortable checking my work and thinking about what could go wrong.

## How can I ensure that my code, program, or software is functional and secure?

I can start by making sure my code meets the requirements and testing more than just the inputs that should work. I also need to check invalid inputs, missing information, and limits on things like field lengths. Testing helps me catch mistakes, but I know passing tests does not mean everything is secure. Reviewing my code and learning more about security are things I want to keep working on.

## How do I interpret user needs and incorporate them into a program?

I start by breaking down what the user wants into smaller requirements that I can work on and test. If something is unclear, asking questions is better than guessing. Working on the contact service helped me see how specific requirements, like keeping an ID unique or limiting a field’s length, affect the code. I am learning to keep those needs in mind throughout the project.

## How do I approach designing software?

I like to break the project into smaller pieces so it feels more manageable. I think about what each part needs to do, build it a step at a time, and test as I go. Sometimes I need to go back and change something when I find a mistake or understand the problem better. I am getting more comfortable with that process, and I am excited to keep learning how to build software that works well and is easier to maintain.
